# Contributing

Thanks for your interest. INeedInfo is a team of two, so a little structure keeps things moving.

## Before you start

- Open an issue first and describe what you want to change and why. We would rather agree on the idea before you write code.
- Look at the project's own README. A project may have its own contributing notes, and those win over this page.

## Pull requests

- Keep one change per pull request, and describe what it does and how you checked it.
- Our tools hold to a few promises: they ask before they change anything on a machine, they collect no telemetry, and every install can be undone. A change that weakens one of these will not be merged.
- Every merge is reviewed by a maintainer. We may ask for changes or decline a change that does not fit the project.
- If you used an AI tool for part of your contribution, say so in the pull request. We build with AI ourselves and have no objection, we just want to know.

## Translations and documentation

Fixes to wording, translations and documentation are welcome and follow the same steps.
